# 修复权限分级表（pav 执行层铁律）

> 依据用户产品架构规范：差异化权限 + 沙箱先行 + 上限交接。任何修复动作执行前先查此表。

## 分级总表

| 级别 | 名称 | 谁来改 | 自动化策略 | 典型场景 |
|---|---|---|---|---|
| L0 | 自动执行 | pav（先沙箱备份） | 自动改 → 回归验证 → 事后人工评审 | 纯 console.log 行清理；wx API 明确近似匹配（相似度 ≥0.82）拼写更正 |
| L0m | 中风险白名单自动 | pav（先沙箱备份，仅 --auto-level medium / optimize 模式） | 自动改 → 回归验证 → 事后人工评审 | 补缺失页面/组件占位四件套（标注 pav 占位待替换）；明文 http→https |
| L1 | 补丁待审批 | pav 生成 diff，人审批后应用 | 写 `.pav/patches/*.diff`，不改真实文件 | 密钥外置、本地地址提取配置、补 tabBar 图标占位提示 |
| L2 | 只出方案 | 人编写（或逐行审批 AI 方案） | 写进改进优化方案.md，零落码 | 拆分超长文件/函数、提取重复代码、UI 交互修复（补 hideLoading/fail 回调）、TODO 消化 |
| L3 | 禁止自动 | 人（必须附需求出处） | 拒绝执行，报告说明 | **断言/测试期望变更、删除用例、数据模型变更、删除功能** |

## 执行前置条件（全部满足才允许动手）

1. 该问题已在 plan 中有任务编号与权限级别标注；
2. `attempts.json` 中该问题尝试次数 < 3；
3. L0 动作已成功创建沙箱备份（`.pav/backup/<ts>/`）；
4. 用户已知晓 L0 将自动执行（首次运行时）。

## 失败处理

- L0 修复失败 → 保留现场（不还原备份），计入 attempts，下一轮闭环重新诊断；
- 达到 3 次 → 写 `.pav/交接报告.md`（问题/尝试记录/建议），该问题退出自动循环；
- verify 发现可疑修复（无改动证据的问题消失 / 骤减文件）→ 返回码 2，报告中原样列出，不得计为成功。

## 禁止清单（任何级别都不许）

1. 放宽断言/期望值让红灯变绿；
2. 删除失败测试或跳过用例；
3. 删除扫描问题清单条目来"清零"；
4. 修改 `.pav/` 内的历史记录（attempt/verify 日志是审计证据）。
